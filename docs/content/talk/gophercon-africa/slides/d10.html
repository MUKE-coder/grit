The migration that half ran.

On production, at the statement that failed. No record of which ones applied, no way back, and a database in a state no version of the code expects.

gritframework.dev

The one that produces the worst evening. Writing the forward migration is the easy part and everybody does it. What is missing is the record: which statements in that run actually applied, and what reverses them. Without that, recovery is a person reading SQL at midnight and guessing. With it, the run has an identifier and a rollback, and the worst case is a boring command.
