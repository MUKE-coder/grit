Checked into the repository, built by CI on every push

examples/commerce

A storefront

Twelve products, a colour and size matrix with ninety-six buyable combinations, a server-side basket.

examples/saas

A subscription product

A customer portal and an operator console, with a test that proves one tenant cannot read another.

examples/library

A lending library

Authors, books, and the loan that connects a book to whoever has it. The smallest honest example.

Each one has a tutorial that rebuilds it from an empty directory, with every command in full.

gritframework.dev

The point of checking these in is that a claim about a framework is worthless unless someone can run it. Commerce is the one to dwell on if there is time. It was built to find faults, and it found seven, all of which are now fixed in the framework rather than worked around in the example. And the tutorials are generated from the applications, not written beside them, so they cannot drift.
