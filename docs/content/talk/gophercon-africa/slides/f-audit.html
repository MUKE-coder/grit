B7 · two logs, on purpose

The timeline

What an operator reads. Named events, deletable, human.

The evidence

Every authenticated write. Append-only. Each row hashes the row before it.

And a verify button, because a hash chain nobody can inspect is indistinguishable from a table with a hash column.

gritframework.dev

The distinction between the two cards is the slide. An operator's timeline and a reviewer's evidence are different products, and trying to serve both with one table serves neither. Then the last line, which is a mistake worth confessing: the chain was implemented, the verify endpoint was implemented, and for a while nothing in the interface called either. So the one feature a compliance reviewer actually asks to see was invisible. The verify walk is deliberately a button rather than something that runs on page load, because it reads the whole table, and firing that on every visit is how an audit feature becomes a performance incident.
