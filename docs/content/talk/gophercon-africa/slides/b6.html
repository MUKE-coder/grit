“What if it gets busy?”

Caching, read replicas, background work, bounded memory. And knowing which of those you actually need, which is the hard part.

The answer, with the commands  gritframework.dev/problems/b6

gritframework.dev

Be honest here, because you will be honest about it again on the scorecard. A framework can give you the cache, the replica support and the job queue. It cannot tell you which one your bottleneck needs. That judgement stays with the engineer, and saying so buys credibility for everything else you claim.
