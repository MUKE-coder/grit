Do not read these. Run them and let the output scroll, because the scroll is the point. One field is worth pointing at: number:string:auto:INV on the Invoice. It fills itself from a sequence on insert, so the first invoice is INV-0001 and nobody types it. The payoff is on the next screen: Payment's invoice dropdown shows that number instead of a UUID, because the admin looks for a label column on the related model and number is one of the names it looks for. Choosing an invoice to pay is reading INV-0007, not a hexadecimal string. If you want one number on stage: four descriptions produced what the previous thirteen slides listed, four times over.
