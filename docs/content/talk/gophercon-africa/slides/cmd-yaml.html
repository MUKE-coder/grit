Or put it in a file

A long command is a file you have not written yet.

# project.yaml
name: Project
owned_by: user
fields:
  - client:belongs_to
  - name:string
  - brief:richtext
  - kind:select[one_off, recurring]
  - cycle:select[monthly, annually]
    if kind == recurring
  - amount:money
  - starts:date
  - gallery:files[image]

$ grit generate resource Project \
    --from project.yaml

Same syntax, one field per line.

It goes in the repository, so the shape of the resource is reviewed in a pull request like everything else, and regenerating it a year later is one command rather than archaeology.

A field with more to say than one line holds can still be written as keys.

Short slide, and it answers the question somebody is already forming: that command is getting long. The file takes exactly the same field syntax, one per line, so nothing new to learn. The reason to prefer it is not the typing. It is that the description of your domain ends up in the repository, reviewed in a pull request, next to the code it generated. Mention the practical one: this is how you regenerate a resource a year later without reconstructing a command from your shell history.
