Step three · a field that only sometimes applies

A billing cycle belongs to a recurring project and means nothing on a one-off one. Four words in the command, and both halves of that rule are written for you.

$ grit generate field Project \
    "cycle:select[monthly, annually] if kind == recurring"

// the form, for the person
visibleWhen:  (v) => v.kind === "recurring"
requiredWhen: (v) => v.kind === "recurring"

// the model, for every other writer
Cycle string `json:"cycle" requiredif:"kind=recurring"`

Slow down here. This is the slide where the demo stops being a scaffold and starts being a domain. Point at the yellow part, which is the whole slide: if kind == recurring. Then point at the two things under it, because they are different jobs. The form stops asking a question that does not apply, and clears a cycle left behind by a project that used to be recurring. The tag refuses the row for every other writer: the API, a CSV import, a job, a script. Doing only the first is how bad data arrives through an import. The honest bit, and say it: this modifier did not exist a week ago. Building this demo is what found it missing. That is the whole feedback loop, in one field.
