Step three · the part the generator does not know

A billing cycle only makes sense on a recurring project. That is a rule about your business, so it lives in your code, in the two places the framework leaves for exactly this.

// internal/services/project.go — the rule, for every caller
if p.Kind == "recurring" && p.Cycle == "" {
    return ErrCycleRequired
}

// resources/projects/custom.tsx — the form, for the human
hidden: (form) => form.kind !== "recurring"

gritframework.dev

This is the most honest slide in the demo, so do not rush it. The generator gives you the field. It cannot know that one field only applies when another has a particular value, because that is domain knowledge. Two places, and they are different jobs. The service refuses it for every caller: the API, the CSV import, a job, a script. The form hides it so a person is never asked a question that does not apply. Doing only the second one is how bad data gets in through an import.
