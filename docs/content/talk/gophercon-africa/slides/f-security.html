B2 · four layers on one sign-in form

01  a rate limit on the route

02  a lockout on the account

03  a growing delay on repeated failure

04  and a locked account answers exactly like a wrong password

The fourth one is the one that gets missed. A helpful error message is an account enumeration oracle.

gritframework.dev

Read the four, then spend the time on the fourth. If a locked account says "this account is locked" and an unknown one says "no such user", you have built a tool for finding out who banks with your client. The polite error message is the vulnerability. The same trap sits in the timing. If the locked path returns instantly and the real check takes eighty milliseconds, the attacker reads the clock instead of the message. So the delay has to be on both paths, which is the kind of detail that is obvious once stated and absent from almost every hand-rolled login.
