“Does it talk to our other systems?”

Outbound events, signed, retried, and not lost because the process died between the database commit and the HTTP call.

gritframework.dev

This is the question that arrives from the client's own technical person, and it is the one that makes you sound either competent or improvised. The naive version is a POST at the end of the handler. It works in the demo and loses events in production, because the commit succeeded and the HTTP call did not, and there is no record that anything was owed. The real requirement is a queue in the same transaction as the write, then a worker that delivers it, retries with a backoff, and signs it so the receiver can tell it is you.
